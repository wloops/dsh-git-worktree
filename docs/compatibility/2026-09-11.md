# 2026-09-11 compatibility check: plugin 0.8.0 / DSH 0.1.5-rc.1

## Result / 结论

**Partially verified; no confirmed plugin runtime incompatibility in the exercised paths.** 用户反馈可用，隔离安装、Host 配置、关键包 import 与 strict Remote 检查支持该反馈。不能将上游 breaking-change 清单直接解释为本插件一定失效，也不能将成功启动解释为所有功能兼容。

没有升级插件依赖、没有修改运行时代码、没有改变 Workspace SHA-256 门禁或 Local 安全模型。本次只补齐发布检查遗漏并改善兼容文档；不建议仅为本次部分验证紧急发兼容版本，可并入下一次正常维护版本。完整新 Host UI/Session 生命周期验收完成前，不扩大 peer 范围、不承诺连续版本支持。

### Browser limitation

The plugin-enabled official Profile reached the API-key onboarding step. Clicking “Configure later” did not leave that screen in this browser session. A separate **plugin-free** official Profile also failed to advance from its welcome step through the same browser tooling. This comparison does not identify the cause: it may involve the browser interaction environment or upstream onboarding. It is **not sufficient evidence to blame the plugin**, and it is not a successful UI activation/full workflow result. No fake API key, modified upstream bundle or hidden onboarding bypass was used to manufacture a pass.

## Interface impact inspection

- **Agent / Inbox:** plugin tools and commands obtain the Agent from invocation arguments; no direct `ctx.agent` or constructed `Inbox` dependency was found. New-Host Remote tests exercise Agent lookup, including missing identity rejection.
- **Session V3 / SessionHandle:** plugin lookup uses Workspace projection and a minimal live Session header fallback, rather than owning the Harness log format. Client orchestration awaits public `sessions.create` and consumes `binding`. This reduces direct migration exposure but does not prove fork/resume/Recovery semantics on the new Host; they remain a validation gap.
- **Client panels:** upstream moves the root `conversation` Slot into `main`. Our views register more specific conversation slots and derive an older Workspace factory, so the headline rename alone does not prove breakage. Actual post-onboarding rendering still needs validation.
- **Workspace provider:** new Host focused tests passed enable/disable lifecycle behavior. The source/hash gate remains a build-time derivation contract, not a runtime ban on newer Hosts.
- **Local safety:** no CAS, confirmation, ownership, cleanup or recovery checks were relaxed. Existing regression tests passed; new Host real-session safety integration remains unverified.

## Reproduction outline

Use a fresh evidence directory, fresh `DSH_HOME` and disposable test repositories. Do not point this procedure at personal session data.

```bash
# Plugin repository (existing lockfile)
pnpm install --frozen-lockfile --ignore-scripts
pnpm run typecheck
pnpm run build
pnpm run test
pnpm run check:sidebar-version
pnpm run check:publish
pnpm peers check
npm pack --ignore-scripts --pack-destination <evidence-directory> --json

# Isolated Host directory with @deepseek-ai/dsh pinned to 0.1.5-rc.1
pnpm install --ignore-scripts
# Inspect pnpm-lock.yaml: a pinned CLI alone does not pin transitive DSH packages.
# Set DSH_HOME to a new directory for every following command.
node <isolated-host>/node_modules/@deepseek-ai/dsh/lib/bin.js plugin --profile web add <tarball>
node <isolated-host>/node_modules/@deepseek-ai/dsh/lib/bin.js --profile web --dump-config
node <isolated-host>/node_modules/@deepseek-ai/dsh/lib/bin.js web --host 127.0.0.1 --port <unused-port> --no-open
```

The exact probe, temporary alias configuration, resolved lockfile, release metadata and baseline test log were retained in the session evidence directory. Temporary probes are not a shipped compatibility harness. Do not infer reproducible whole-range support from this dated report.
