# Official Workspace Browser integration

This integration derives at build time from three individually version- and SHA-256-gated MIT-licensed DeepSeek Harness packages: `@deepseek-ai/dsh-client-ui-workspace@0.2.0-rc.2`, `0.1.6-alpha.2`, and `0.1.7-rc.2`. They are build-time aliases, not private runtime copies of Host singleton packages.

The public Slot ledger can elect a lower-priority Browser, but a wrapper entry cannot inherit the original entry's child-slot authorization: omitting `children` removes the `renderSlot` seat, while repeating `children` redeclares `sidebar.workspaces.directoryFlow`. Therefore `cordis.patch.yml` conditionally disables the original loader row only while this plugin's Host provider marker is active and its entry is enabled. `src/workspace-provider-lifecycle.ts` reconciles that selection through public Loader entry update/refresh operations, including late Include activation and disable-list replay, without persisting a disabled flag. On deactivation the marker is released before the official row is restored; explicit user overrides are not replaced. The matching `scripts/workspace-sidebar-upstream*.mjs` embeds each pinned official Client factory. The proxy preserves its official declaration tree, WorkspacePicker, locale dictionaries, stores, and directory-flow behavior. It replaces the Browser data projection and applies exact, fail-closed source seams for Managed owner identity, status, unsafe row operations and new-generation service shortcuts (fail-closed until topology is verified); canonical Session titles and ordinary Local rows remain official behavior. The newer derivatives deliberately preserve the official Browser's changed Hook/Slot contracts rather than transplanting the rc.1 Browser. The rc.2 branch registers its additional menu/action, search and overlay seats under the official authorization tree. On managed rows the registration proxy preserves the official pin, rename and archive entries (including their inverse actions, dialogs and hover controls), even while topology is unverified; these operations do not change owner identity or Workspace membership. Fork and unclassified entries remain guarded. Alpha retains its native menu and filters only fork for managed rows. Service-level guards block owner forks and new Sessions in managed Workspaces, not rename/archive; all derivatives capture the guard on each `uiWorkspace` instance at construction because Cordis derives a Context that does not retain the registration proxy's virtual `get` override. Ordinary rows retain their official actions once topology is verified. The Host-resolved `dsh-agent` package version selects exactly one derivative via strict Remote topology; unknown generations keep the official provider instead of mounting a guessed replacement.

The upstream version and compiled Client SHA-256 are hard gates for each variant. All three follow the split Client architecture: Cordis owns the Context, API Session/Workspace Controllers own list snapshots, and `dsh-client-store` owns browser-local viewing state. `scripts/check-workspace-sidebar-version.mjs`, `scripts/check-publish.mjs`, focused compatibility tests, and a real Chromium DOM/Host probe must all pass before claiming a runtime compatibility combination. The rc.2 variant has been browser-smoked on an isolated source Host (including a managed blank Session and badge spacing); a populated managed Session's hover buttons still require an AI-enabled UI smoke. Alpha.2 has not yet been browser-smoked on an isolated Host. See the repository `NOTICE` for attribution.

Focused regressions execute all three pinned Client factories against Cordis to verify owner rename/archive/unarchive callbacks, native stop-and-archive options, ordinary fork forwarding, and fail-closed owner/new-session guards before and after topology verification. These callback tests do not replace a real Host UI smoke for menu rendering, keyboard bindings or running-work confirmation.
