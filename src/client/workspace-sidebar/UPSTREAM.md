## Native migration boundary

Unknown Hosts now use `native.tsx` to contribute ambient Worktree identity/state through public trailing and hover declaration lifetimes. This branch owns no Browser, service, Controller source, menu, or Session binding and performs no version test. It shares pure task selection with the projection model, coalesces topology reads, ignores stale/disposed responses and withdraws metadata on failure. Known derivative paths remain unchanged to preserve aggregation and constant tag placement until an upstream presentation-projection/identity contract exists. See `docs/SIDEBAR-NATIVE-INTEGRATION.md`: this is a staged migration, not completion of native aggregation. Do not replace the missing contract with mutable ledger entries, global source rewriting or a second official apply.

# Official Workspace Browser integration

This integration derives at build time from four individually version- and SHA-256-gated MIT-licensed DeepSeek Harness packages: `@deepseek-ai/dsh-client-ui-workspace@0.2.1-rc.2`, `0.2.1-rc.5`, `0.1.6-alpha.2`, and `0.1.7-rc.2`. They are build-time aliases, not private runtime copies of Host singleton packages.

The public Slot ledger can elect a lower-priority Browser, but a wrapper entry cannot inherit the original entry's child-slot authorization: omitting `children` removes the `renderSlot` seat, while repeating `children` redeclares `sidebar.workspaces.directoryFlow`. Therefore `cordis.patch.yml` conditionally disables the original loader row only while this plugin's Host provider marker is active and its entry is enabled. `src/workspace-provider-lifecycle.ts` reconciles that selection through public Loader entry update/refresh/init operations, including late Include activation and disable-list replay, without persisting a disabled flag. On deactivation the marker is explicitly released before the official row is restored; Cordis 4.0.5 runs effect cleanup concurrently, so registration order does not guarantee this. Loader 1.0.6 keeps disposed fiber references: disable waits on the fiber, and restore uses public `init()` for a dead generation. Only the matching replacement entry/fiber reference is withdrawn on disposal or failed activation, with the owning `internal/plugin` event notifying the registry; successful same-fiber restarts retain the reference. Explicit user overrides are not replaced and no configuration is persisted. The matching `scripts/workspace-sidebar-upstream*.mjs` embeds each pinned official Client factory. The proxy preserves its official declaration tree, WorkspacePicker, locale dictionaries, stores, and directory-flow behavior. It replaces the Browser data projection and applies exact, fail-closed source seams for Managed owner identity, status, unsafe row operations and new-generation service shortcuts (fail-closed until topology is verified); canonical Session titles and ordinary Local rows remain official behavior. The newer derivatives deliberately preserve the official Browser's changed Hook/Slot contracts rather than transplanting the rc.1 Browser. The rc.2 branch registers its additional menu/action, search and overlay seats under the official authorization tree. On managed rows the registration proxy preserves the official pin, rename and archive entries (including their inverse actions, dialogs and hover controls), even while topology is unverified; these operations do not change owner identity or Workspace membership. Fork and unclassified entries remain guarded. Alpha retains its native menu and filters only fork for managed rows. Service-level guards block owner forks and new Sessions in managed Workspaces, not rename/archive; all derivatives capture the guard on each `uiWorkspace` instance at construction because Cordis derives a Context that does not retain the registration proxy's virtual `get` override. Ordinary rows retain their official actions once topology is verified. The Host-resolved `dsh-agent` package version selects exactly one derivative via strict Remote topology; unknown generations keep the official provider instead of mounting a guessed replacement.

The rc.5 alias is independently name/version/SHA-256 gated (`9c2c17a66a5c20de00ac2852cb76debb5237439e97f877403bcaa2a471086544`). It shares only the exact managed decoration transform with rc.2, not its source or factory: rc.5's changed `connectBlank`, preset-aware `createInWorkspace`, and `startSession`/`whenDraftExists` remain official rc.5 behavior. The Host-resolved `dsh-agent@0.2.1-rc.5` selects `modern-rc5` through the strict Remote codec; rc.2 remains `modern`. No other 0.2.1 RC is inferred compatible. Development singleton packages remain rc.2; the rc.5 alias is build source, not a second runtime singleton.

The upstream version and compiled Client SHA-256 are hard gates for each variant. All four follow the split Client architecture: Cordis owns the Context, API Session/Workspace Controllers own list snapshots, and `dsh-client-store` owns browser-local viewing state. `scripts/check-workspace-sidebar-version.mjs`, `scripts/check-publish.mjs`, focused compatibility tests, and a real Chromium DOM/Host probe must all pass before claiming a runtime compatibility combination. The previous 0.2.0-rc.2 variant was browser-smoked on an isolated source Host (including a managed blank Session and badge spacing); that historical result does not accept the current 0.2.1-rc.2 derivative. Historical rc.2 source validation (while plugin version was 0.10.1) passed typecheck, build, source/hash and publish gates plus 607 tests (1 skipped). The current unreleased rc.5 addition (package version still 0.12.0) additionally tests both emitted modern Browser branches for aggregation, canonical titles, owner badges, distinct navigation semantics and slot declarations; four-generation CSS ownership/rematerialization; exact-source semantic and provenance gates; and real Loader disable/re-enable. These are isolated source/jsdom regressions, not rc.5 Host, real browser, AI, desktop or Windows acceptance. A populated managed Session's hover buttons still require an AI-enabled UI smoke. Alpha.2 has not yet been browser-smoked on an isolated Host. See the repository `NOTICE` for attribution.

Embedded factories also retain upstream CSS bytes/class maps but rewrite each CSS tag’s owner to `dsh-git-worktree` and its deduplication key to `dsh-git-worktree/workspace-<exact-version>/<file>`. All four factories materialize eagerly; sharing upstream keys would let the first generation suppress the others, and sharing upstream ownership would let official-module teardown remove derivative styles. The source transform fails closed on the expected CSS tag count (rc.2/rc.5/next: four; alpha: three). Built-artifact jsdom regressions cover both materialization orders, exact CSS bytes, official cleanup/rematerialization and plugin cleanup/rematerialization; these are not real Host HMR acceptance.

Focused regressions execute all three pinned Client factories against Cordis to verify owner rename/archive/unarchive callbacks, native stop-and-archive options, ordinary fork forwarding, and fail-closed owner/new-session guards before and after topology verification. These callback tests do not replace a real Host UI smoke for menu rendering, keyboard bindings or running-work confirmation.
